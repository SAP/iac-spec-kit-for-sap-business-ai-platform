# BTP IaC — Analyse

Analyses code to extract concrete infrastructure signals and enriches `specs/scenario.md` in place.

## Workflow

**Phase 1 — Ask what to analyse**: Ask the user whether they want to analyse (a) existing **application source code** or (b) **Terraform code**. Do not proceed without a clear answer.

**Phase 2 — Locate the code**: Ask for the path to the code if not already provided.

**Phase 3 — Detect format and read** (existence checks before full reads; stop at first match per branch):

*Application source code:*
1. `mta.yaml` present → **MTA** — read `mta.yaml`, `xs-security.json` (if present), `xs-app.json` (if present)
2. `package.json` contains `@sap/cds` → **CAP** — read `package.json` (dependencies only), `schema.cds` (entity names only), `xs-security.json` (if present)
3. `manifest.yml` present → **CF** — read `manifest.yml`
4. None matched → report unsupported format and stop.

*Terraform code:*
- Read `*.tf` files in this order: `providers.tf` or `versions.tf`, `variables.tf`, `main.tf`, then any module `*.tf` files. Stop reading once signals are found; do not read all files if early reads are sufficient.

**Phase 4 — Extract signals**:

*From source code:*
- **services** — BTP service instances (name, service, plan)
- **memory** — per-module memory quotas
- **roles** — role definitions from `xs-security.json` (name, scope)
- **artifacts** — build artifact names and types

*From Terraform code:*
- **resources** — `resource` blocks (type, name)
- **modules** — `module` blocks (name, source)
- **variables** — input variables with their types and defaults
- **providers** — required providers and versions

**Phase 5 — Enrich `specs/scenario.md`**: Add or update an `## Infrastructure Signals` section at the end of the file. Do not rewrite existing sections. Render each signal category as a markdown table; omit any table with no data. Mark the section with `<!-- auto-generated by /btp-iac.analyse -->` so re-runs can identify and replace it without touching the rest of the file.

## Tool preferences

Before using `WebFetch` to look up SAP documentation, check if the `sap-docs` MCP server is available (tools prefixed `mcp__sap-docs__*`). If yes, use it. If not, fall back to `WebFetch`.
